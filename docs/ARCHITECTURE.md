# 박승민.log 아키텍처

## 한 문장으로 이해하기

마크다운이 원본이고, Astro는 `status: public`인 원본만 독자가 보는 HTML로 바꾸는 **출판기**입니다. 관리자 에디터는 원본을 편하게 만드는 **집필 도구**이며, 공개 사이트 자체는 로그인이나 데이터베이스 없이 작동합니다.

```text
                         ┌─ 임시 저장 ─▶ 비공개 원고 저장소
[관리자 에디터] ─▶ [OAuth API]
                         └─ 발행 ─────▶ 공개 블로그 저장소
                                                │ push
                                                ▼
                                        [GitHub Actions]
                                                │ public만 빌드
                                                ▼
                                         [GitHub Pages]
                                                │
                                                ▼
                                              독자
```

## 왜 객체와 책임을 나눴는가

이 프로젝트의 핵심 객체는 세 가지입니다.

| 객체 | 책임 | 몰라야 하는 것 |
| --- | --- | --- |
| Post(마크다운 + Front Matter) | 글의 내용과 발행 대상을 표현 | 화면 배치, 배포 방법 |
| Page(홈/아카이브/상세) | 공개 Post를 읽어 화면으로 표현 | OAuth 토큰, 비공개 원고 |
| Editor | Post를 만들고 저장을 요청 | GitHub OAuth 비밀값 |

좋은 설계의 직관은 “한 객체가 바뀌는 이유를 하나로 줄이는 것”입니다. 글 제목을 고쳤다고 배포 코드가 바뀌면 안 되고, OAuth 공급자를 바꿨다고 글 화면이 바뀌면 안 됩니다. 그래서 콘텐츠, 표현, 인증을 각각 분리했습니다.

## 상태 모델

```text
비공개 저장소: draft ──발행──▶ public :공개 저장소
                    ▲             │
                    └─수정 초안 저장┘
                       (공개본 유지)
```

사용자가 고르는 공개/비공개 상태 전환은 없습니다. 두 버튼은 상태 선택이 아니라 서로 다른 명령입니다.

| 명령 | 쓰는 위치 | 기존 공개본 |
| --- | --- | --- |
| 임시 저장 | 비공개 원고 저장소의 `draft/{slug}.md` | 변경하지 않음 |
| 발행 | 공개 저장소의 `src/content/posts/{slug}.md` | 새 내용으로 생성 또는 갱신 |

발행에 성공하면 같은 슬러그의 초안은 비공개 원고 저장소에서 정리합니다. 반대로 공개된 글을 불러와 임시 저장할 때는 공개 저장소를 건드리지 않습니다. 그래서 글을 고치는 동안 기존 독자는 마지막으로 발행된 버전을 계속 읽습니다.

정적 화면 생성 조건은 단 하나입니다.

```ts
post.status === 'public'
```

이 조건을 홈, 아카이브, 상세 URL, RSS가 모두 같은 콘텐츠 컬렉션에서 사용합니다. 여러 곳에서 서로 다른 조건을 만들지 않아 “목록에는 없는데 URL로는 열리는” 상태 누락을 피합니다.

### 왜 공개 글을 다시 비공개로 돌리지 않는가

GitHub Pages 결과물에서 글을 빼는 것과 이미 공개한 원본을 비밀로 되돌리는 것은 다른 문제입니다. 공개 저장소에서 글 파일을 삭제하면:

1. 사이트 메뉴와 RSS에서는 사라질 수 있습니다.
2. 그러나 이전 커밋의 Git 히스토리에는 내용이 남습니다.
3. 검색 엔진, RSS 리더, 브라우저 캐시나 다른 사람이 저장한 복사본도 회수할 수 없습니다.

따라서 에디터는 `public → private` 전환을 제공하지 않습니다. 발행 전 원고만 처음부터 비공개 저장소에 두는 것이 실제 보안 경계입니다. 발행 글 삭제는 현재 빌드에서 글을 내리는 **노출 중단**이며 **비밀 복구**가 아닙니다. 삭제 확인창과 완료 안내도 이 차이를 명시합니다.

## 안전한 slug 변경

slug는 파일 이름이면서 공개 URL의 일부입니다. 새 slug를 바로 덮어쓰거나 옛 파일부터 지우면 다른 글을 덮거나 실패 중 원본을 잃을 수 있습니다.

```text
1. 불러온 파일 SHA 확인 ── 달라짐 ──▶ 409 충돌, 다시 불러오기
             │ 같음
             ▼
2. 새 slug 사용 여부 확인 ── 사용 중 ─▶ 409 충돌, 저장 중단
             │ 비어 있음
             ▼
3. 새 파일 저장 ── 성공 ──▶ 옛 파일 삭제
             │
             └─ 공개 글이면 aliases에 옛 slug 추가
                                      │
                                      ▼
                         옛 URL ──정적 이동 페이지──▶ 새 URL
```

새 파일을 먼저 쓰므로 중간 실패가 나도 원본을 잃지 않습니다. GitHub Contents API는 여러 파일 작업을 하나의 트랜잭션으로 묶지 않으므로 두 커밋 사이에 옛 파일과 새 파일이 잠깐 함께 존재할 수는 있지만, 데이터가 사라지는 순서는 피합니다. 최종 빌드에서는 옛 slug 파일이 사라지고 `aliases` 기반 정적 이동 페이지만 남습니다.

GitHub Pages는 서버 측 HTTP 301 규칙을 제공하지 않습니다. 따라서 옛 경로에는 Astro가 `noindex`, canonical, 즉시 이동 메타태그를 가진 HTML을 생성합니다. 기존 링크와 사용자는 새 주소로 이동하지만, 서버가 직접 반환하는 진짜 301 응답과는 다릅니다.

초안이 발행 글에서 갈라진 수정본이면 비공개 Front Matter에 `publishedSlug`와 `publishedSha`를 함께 기록합니다. 에디터를 닫았다 다시 열어도 어느 공개본을 수정 중이었는지 복원하고, 그 공개본이 다른 곳에서 변경됐다면 발행을 중단할 수 있습니다.

## 삭제 규칙

| 선택한 원본 | 삭제 대상 | 자동으로 남기는 것 |
| --- | --- | --- |
| 임시 저장 글 | 비공개 저장소의 해당 초안 파일 | 공유 가능성이 있는 업로드 이미지 |
| 발행 글 | 공개 저장소의 해당 글 파일 | 별도 임시 저장본, Git 히스토리 |

삭제도 불러올 때 받은 Git SHA가 현재 SHA와 같을 때만 허용합니다. 목록을 연 뒤 다른 곳에서 글이 바뀌었다면 오래된 화면에서 삭제하지 못하고 다시 불러오게 합니다.

### 이미지가 항상 초안 저장소를 먼저 거치는 이유

글이 아직 초안인데 이미지를 공개 저장소에 먼저 올리면 파일 URL과 Git 기록이 이미 공개됩니다. 따라서 에디터의 이미지 업로드는 현재 글이 새 글인지, 기존 공개 글의 수정본인지와 관계없이 비공개 원고 저장소에만 커밋합니다. 발행 API가 본문에서 참조한 이미지들만 공개 저장소로 복사합니다.

## 에디터 인증 경계

GitHub OAuth Web Flow는 `client_secret`을 요구합니다. 정적 JavaScript에 비밀값을 넣으면 브라우저 개발자 도구와 배포 파일에서 그대로 노출됩니다.

```text
안전하지 않음: 브라우저 ── client_secret 포함 ──▶ GitHub
안전함:       브라우저 ── HttpOnly 세션 ──▶ OAuth API ── secret ──▶ GitHub
```

에디터는 `PUBLIC_EDITOR_API_URL`에 다음 계약을 기대합니다. 이 계약의 Cloudflare Worker 구현은 `editor-api`에 포함되어 있습니다.

| 요청 | 역할 |
| --- | --- |
| `GET /auth/login` | GitHub 로그인 시작 |
| `GET /api/session` | 허용된 작성자 로그인 상태 확인 |
| `GET /api/posts` | 초안과 발행 글 목록 조회 |
| `GET /api/posts/{draft\|public}/{slug}` | 편집할 원문 조회 |
| `POST /api/posts` + `status: draft` | 공개본을 건드리지 않고 임시 저장 |
| `POST /api/posts` + `status: public` | 공개본 생성·갱신 후 해당 초안 정리 |
| `DELETE /api/posts/{draft\|public}/{slug}` | SHA가 일치하는 선택 원본 삭제 |
| `POST /api/images` | 이미지를 비공개 원고 저장소에 커밋 |

API는 로그인 뒤 `GET /user`로 GitHub 아이디를 확인하고, 환경 변수 `ALLOWED_GITHUB_LOGIN`과 정확히 같을 때만 쓰기를 허용합니다. 토큰은 JavaScript가 읽을 수 없는 암호화된 `HttpOnly; Secure; SameSite=None` 쿠키에 보관합니다. GitHub Pages와 Worker가 서로 다른 오리진이므로 쿠키는 `None`이 필요하고, 대신 허용 오리진 고정과 CSRF 토큰 검사를 함께 적용합니다.

## 폴더 구조

```text
src/content/posts/       글 원본
src/pages/               홈·아카이브·상세·에디터·RSS
src/layouts/             공통 HTML/SEO 구조
src/components/          헤더·푸터·글 메타 같은 재사용 단위
src/styles/              공통 디자인 토큰과 기본 스타일
.github/workflows/       공개 빌드와 GitHub Pages 배포
```
