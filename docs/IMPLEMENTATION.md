# 도토리 창고 실사용 개선

홈은 실제 공개 글에서 목록과 주제 메뉴를 생성한다. 자유 검색과 정확한 태그 필터를 조합하고 주소에 필터를 유지한다. 책갈피는 현재 기기에 보관한다. 이름은 도토리 창고, 글쓴이는 기존 박승민을 유지한다.

관리자는 제목과 Markdown 본문 중심이다. 태그는 Enter로 추가하고 기존 태그를 추천한다. 날짜·분류·요약·주소·썸네일은 추가 설정에 둔다. 새 기록은 별도 ID로 생성하고 원고별로 500ms 후 기기에 저장한다. 이전 단일 자동 저장본은 원본 키를 지우지 않고 가져온다. 기기 초안과 비공개 저장소의 임시 저장은 별도 상태다. 기기를 바꿔 이어 쓰려면 임시 저장을 사용한다.

검증한 SHA를 최종 GitHub 쓰기에 전달하여 동시 저장을 거부한다. 글 생성은 기존 파일 SHA를 자동 채택하지 않는다. 공개 저장 이후 파일 정리만 실패하면 본문 저장 성공과 후처리 경고를 함께 반환한다. 미완성 초안은 요약·분류·본문 없이도 저장 가능하다. 발행은 제목·본문을 요구한다.

로그아웃은 CSRF를 확인하고 세션 쿠키를 만료한다. 서버 저장 전 로그인 상태를 재확인하고 만료 시 기기의 원고를 유지한 채 재로그인을 안내한다. API는 요청 Origin을 변경 수행 전에 확인한다. 원고의 이미지는 인증된 조회 API로 미리 보고, 프로젝트 Pages의 이미지에는 base 경로를 붙인다.

## 디자인 통일성 검사

landing-page-design SKILL.md를 적용해 작성 화면에 중첩되던 기존 스타일을 editor.css 하나로 정리했다. 공통 modern.css에서 Pretendard, 중성 바탕, 224px 사이드바, 글자 크기 단계, 간격, 버튼/입력/포커스를 맞춘다. 날짜·요약 등 보조 설정은 접고, 보조 동작은 더보기에 둔다.

사용자 지시가 스킬 기본값보다 우선한다: Pretendard 유지, 슬로건/히어로/그라데이션/프로모션 섹션 없음, 단순한 텍스트 이름. 이 앱은 개인 기록 도구이므로 전환용 마케팅 구조를 추가하지 않는다. 코드/이미지/본문 등 사용자가 작성한 콘텐츠의 의미는 디자인 감사로 바꾸지 않는다.

## 검증

- npm test: 버전 충돌, 생성 보호, 미완성 초안, 인증/CSRF/로그아웃, 글별 복구, 잘못된 저장소 보존, 정확한 태그, 이미지 base.
- node tests/verify-build.mjs: 일회용 공개·비공개 글로 실제 /blog/ 빌드. 공개 목록, 비공개 제외, 글 링크, 이미지 경로, GFM 표 확인. 검증 원고는 finally에서 제거.
- 앱 내 브라우저에서 원고 A 작성 → 새 원고 B → A 선택 → 새로고침 후 내용 보존 확인. 모바일 390px에서 넘침 없음. 데스크톱 1440px에서 Pretendard 계산 스타일 확인.

실제 GitHub OAuth 로그인과 운영 저장소의 글 생성·삭제는 수행하지 않았다. API 변경은 별도의 Worker 배포가 필요하다. 로컬 원고 충돌은 저장 시 버전 비교로 감지하며 여러 브라우저 프로세스의 완전한 동시 쓰기를 원자적으로 보장하는 저장소는 아니다. 운영 API의 충돌 거부는 GitHub의 SHA 조건부 쓰기를 사용한다.

기기의 초안 삭제는 보관 처리하며 더보기에서 최근 삭제 초안을 복구할 수 있다. 실제 서버의 삭제와 기기의 초안 삭제를 구분한다.
